## 一、Java 基础

**1. == 和 equals() 的区别？**
== 比较的是内存地址（基本类型比较值）；equals() 默认也是比较地址，但 String、Integer 等类重写了它，变成比较内容。

**2. ArrayList 和 LinkedList 的区别？**
ArrayList 底层是数组，查询快、增删慢；LinkedList 底层是双向链表，查询慢、增删快。

**3. HashMap 的底层原理？JDK1.8 优化了什么？**
底层是数组 + 链表 + 红黑树。JDK1.8 在链表长度超过 8 且数组长度 ≥ 64 时，会把链表转成红黑树，查询效率从 O(n) 提升到 O(logn)。

**4. HashMap 和 ConcurrentHashMap 的区别？**
HashMap 线程不安全，多线程下可能死循环；ConcurrentHashMap 线程安全，JDK1.8 用 CAS + synchronized 锁单个桶，并发性能高。

**5. 多线程的创建方式有哪几种？**
① 继承 Thread 类；② 实现 Runnable 接口；③ 实现 Callable 接口 + FutureTask；④ 使用线程池。

**6. synchronized 和 Lock 的区别？**
synchronized 是关键字，自动加锁释放锁；Lock 是接口，需要手动 lock() 和 unlock()，但更灵活，支持公平锁、可中断、超时。

**7. 线程池的核心参数有哪些？执行流程？**
核心参数：核心线程数、最大线程数、空闲存活时间、时间单位、阻塞队列、线程工厂、拒绝策略。
执行流程：核心线程满 → 进队列 → 队列满 → 开新线程到最大数 → 还满 → 触发拒绝策略。

**8. JVM 内存结构？**
堆（对象）、虚拟机栈（方法局部变量）、本地方法栈、方法区（类信息、常量）、程序计数器。

**9. 垃圾回收机制？常见回收器？**
GC 通过可达性分析判断对象是否存活。常见回收器：Serial、ParNew、Parallel Scavenge、CMS、G1。JDK9 后默认 G1。

**10. 面向对象三大特性？**
封装（隐藏细节）、继承（复用代码）、多态（父类引用指向子类对象，一个接口多种实现）。

## 二、Spring / SpringBoot / MyBatis

**1. 什么是 IOC？什么是 AOP？**
IOC（控制反转）：对象的创建和依赖交给 Spring 容器管理，不用自己 new。
AOP（面向切面）：把日志、事务等公共逻辑抽出来，在不改业务代码的情况下增强功能。

**2. Spring Bean 的生命周期？**
实例化 → 属性赋值 → 初始化（@PostConstruct）→ 使用 → 销毁（@PreDestroy）。

**3. Spring Bean 的作用域？**
singleton（默认，单例）、prototype（多例）、request、session、application。

**4. Spring 事务实现原理？@Transactional 失效场景？**
基于 AOP 实现，通过代理对象在方法前后开启/提交事务。
失效场景：① 方法不是 public；② 自调用（同类内部方法调用）；③ 异常被 catch 没抛出；④ 数据库引擎不支持事务。

**5. SpringBoot 自动装配原理？**
@SpringBootApplication 包含 @EnableAutoConfiguration，它会读取 META-INF/spring.factories（或 2.7+ 的 AutoConfiguration.imports）里配置的类，按条件自动装配 Bean。

**6. SpringBoot 和 Spring 的区别？**
SpringBoot 是 Spring 的简化版，省去了繁琐的 XML 配置，内置 Tomcat，提供 starter 依赖，开箱即用。

**7. MyBatis 中 #{} 和 ${} 的区别？**
#{} 是预编译，用 ? 占位，防 SQL 注入；${} 是字符串拼接，有 SQL 注入风险，一般用在表名、排序字段。

**8. MyBatis 的一级缓存和二级缓存？**
一级缓存：SqlSession 级别，默认开启，同一个 SqlSession 内查询相同 SQL 会走缓存。
二级缓存：Mapper 级别，需要手动开启，多个 SqlSession 共享。

**9. ResultMap 和 ResultType 的区别？**
ResultType：自动映射，要求数据库列名和实体属性名一致。
ResultMap：手动映射，可以处理列名和属性名不一致、一对多、多对一。

**10. MyBatis 分页插件原理？**
通过拦截器拦截 SQL，在 SQL 后面自动拼接 LIMIT 语句，并执行一条 COUNT 查询总数。

## 三、MySQL

**1. 事务的四大特性（ACID）？**
原子性（要么全成功要么全失败）、一致性（数据前后一致）、隔离性（事务之间互不干扰）、持久性（提交后永久保存）。

**2. 事务的隔离级别？MySQL 默认？**
读未提交、读已提交、可重复读（MySQL 默认）、串行化。

**3. 脏读、不可重复读、幻读？**
脏读：读到别人没提交的数据。
不可重复读：同一事务内两次读同一行结果不一样。
幻读：同一事务内两次读同一范围，行数不一样。

**4. 索引的底层数据结构？为什么用 B+ 树？**
B+ 树。因为：① 非叶子节点只存索引，树矮，磁盘 IO 少；② 叶子节点双向链表，范围查询快；③ 查询性能稳定。

**5. 聚簇索引和非聚簇索引的区别？**
聚簇索引：叶子节点存整行数据（主键索引）。
非聚簇索引：叶子节点存主键值，查询需要回表。

**6. 最左前缀原则？**
联合索引 (a,b,c)，查询条件必须从最左边开始连续匹配，比如 a、a,b、a,b,c 能走索引，b、b,c 不行。

**7. 索引失效的情况？**
① 用 LIKE '%xx' 以 % 开头；② 在索引列上做运算或函数；③ 类型隐式转换；④ 用 OR 连接非索引列；⑤ 不满足最左前缀。

**8. 回表和覆盖索引？**
回表：通过非聚簇索引找到主键，再回聚簇索引查整行数据。
覆盖索引：查询的列全在索引里，不用回表。

**9. MySQL 的锁？**
按粒度：表锁、行锁、间隙锁。按模式：共享锁（S）、排他锁（X）。InnoDB 默认行锁。

**10. 如何优化 SQL？**
① 加合适索引；② 避免 SELECT *；③ 用 EXPLAIN 看执行计划；④ 开启慢查询日志；⑤ 减少子查询，用 JOIN。

## 四、Redis

**1. 常用数据类型和场景？**
String（缓存、计数器）、Hash（对象）、List（消息队列）、Set（去重、抽奖）、ZSet（排行榜）。

**2. Redis 为什么快？**
① 纯内存操作；② 单线程避免上下文切换；③ IO 多路复用；④ 高效的数据结构。

**3. 缓存穿透？怎么解决？**
查询不存在的数据，请求打到数据库。
解决：① 缓存空值；② 布隆过滤器。

**4. 缓存击穿？怎么解决？**
热点 Key 过期瞬间，大量请求打到数据库。
解决：① 互斥锁；② 热点数据永不过期。

**5. 缓存雪崩？怎么解决？**
大量 Key 同时过期，或 Redis 宕机。
解决：① 过期时间加随机值；② 搭建集群；③ 服务熔断降级。

**6. Redis 持久化机制？**
RDB：定时快照，恢复快，可能丢数据。
AOF：记录写命令，数据安全，恢复慢。

**7. 过期策略和内存淘汰策略？**
过期策略：惰性删除 + 定期删除。
淘汰策略：LRU、LFU、Random、TTL 等 8 种，默认 noeviction。

**8. 如何用 Redis 实现分布式锁？**
SET key value NX EX 加锁，value 存唯一标识；释放时用 Lua 脚本判断是自己的锁再删。

**9. Redis 主从复制原理？**
从节点 SLAVEOF 主节点 → 主节点 RDB 全量同步 → 后续 AOF 增量同步。

**10. Redis 集群方案？**
① 主从复制；② 哨兵模式（自动故障转移）；③ Cluster 分片集群（数据分片）。

## 五、微服务 / SpringCloud

**1. 为什么要用微服务？优缺点？**
优点：解耦、独立部署、技术异构、按需扩容。
缺点：运维复杂、分布式事务、网络延迟、调试困难。

**2. Nacos 和 Eureka 的区别？**
Nacos 支持注册中心 + 配置中心，支持 AP 和 CP 切换；Eureka 只支持注册中心，只支持 AP。

**3. Nacos 注册中心原理？**
服务启动时向 Nacos 注册，定期发送心跳；消费者从 Nacos 拉取服务列表，本地缓存 + 定时更新。

**4. OpenFeign 原理？**
基于动态代理，扫描 @FeignClient 接口，生成代理对象，把方法调用翻译成 HTTP 请求，发给目标服务。

**5. OpenFeign 和 RestTemplate 的区别？**
RestTemplate 需要手动拼 URL、手动解析；OpenFeign 是声明式的，像调本地方法一样调远程服务。

**6. Gateway 的作用？和 Nginx 的区别？**
Gateway 是微服务网关，做路由、鉴权、限流、熔断，工作在应用层。
Nginx 是反向代理服务器，做静态资源、负载均衡，性能更高，但功能偏底层。

**7. 服务熔断和服务降级？**
熔断：服务调用失败率达到阈值，自动切断，不再调用。
降级：服务不可用时，返回兜底数据，保证核心功能可用。

**8. 微服务数据一致性？分布式事务？**
方案：2PC、TCC、Saga、本地消息表、Seata。实际项目常用 Seata 的 AT 模式。

**9. CAP 理论？**
C 一致性、A 可用性、P 分区容错性。分布式系统最多满足两个，一般选 AP 或 CP。

**10. 你的项目服务怎么拆分？**
按业务领域拆：商品、购物车、订单、用户、网关。每个服务独立数据库，通过 OpenFeign 调用。

## 六、项目 + 场景题

**1. 介绍“速达外卖”？**
基于 SpringBoot + MyBatis 的外卖系统，分管理端和用户端。我负责后端接口开发，用 Redis 缓存菜品分类，用 Nginx 解决跨域，用 POI 导出 Excel。

**2. 介绍“大众商场”？**
基于 SpringCloud 的微服务电商平台，拆成 5 个服务，用 Nacos 注册、OpenFeign 调用、Gateway 鉴权、Docker 部署。

**3. 项目中最大困难？**
Redis 缓存和数据库数据不一致。解决：更新数据库后删除缓存，并设置过期时间兜底。

**4. 为什么用 Redis 缓存菜品分类？**
菜品分类读多写少，缓存后减少数据库压力，接口响应从 200ms 降到 100ms。

**5. 数据库更新了，Redis 怎么同步？**
先更新数据库，再删除缓存（Cache Aside Pattern），并给缓存设过期时间。

**6. 接口响应提升 50% 怎么测的？**
用 JMeter 或 Postman 压测，对比加缓存前后的平均响应时间。

**7. 微服务一个服务挂了怎么办？**
① 熔断降级（Sentinel）；② 服务重试；③ 集群部署，多个实例。

**8. 用户登录怎么实现？JWT 原理？**
登录成功后生成 JWT Token，包含用户 ID 和签名，返回给前端；前端每次请求带 Token，后端拦截器校验。JWT 由 Header、Payload、Signature 三部分组成。

**9. AOP 用在哪里？**
用在统一日志记录和事务管理上，通过 @Aspect 定义切面，拦截指定方法。

**10. 阿里云 OSS 怎么用？**
引入 OSS SDK，配置 AccessKey，前端上传文件到后端，后端调 putObject 上传到 OSS，返回 URL。
