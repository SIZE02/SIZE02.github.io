## 一句话对比

- 苍穹外卖：单体业务完整，适合讲清 CRUD、订单状态、缓存、支付、统计。
- 黑马商城：微服务架构完整，适合讲服务拆分、注册发现、网关、事务、MQ、ES、Redis。

## 架构对比

| 维度 | 苍穹外卖 | 黑马商城 |
|---|---|---|
| 架构 | 单体 | 微服务 |
| 服务调用 | 本地方法 | OpenFeign |
| 注册中心 | 无 | Nacos |
| 网关 | Nginx | Spring Cloud Gateway |
| 鉴权 | 拦截器 | 网关 + 下游拦截器 |
| 数据库 | 单库 | 分库 |
| 事务 | 本地事务 | Seata / 消息补偿 |
| 缓存 | Redis + Spring Cache | Redis 购物车/缓存 |
| 搜索 | MySQL | Elasticsearch |
| 异步 | Spring Task | RabbitMQ |

## 业务对比

| 能力 | 苍穹外卖 | 黑马商城 |
|---|---|---|
| 用户 | 微信登录 | 账号登录/JWT |
| 商品 | 菜品、套餐 | SKU 商品、库存 |
| 购物车 | MySQL | Redis |
| 订单 | 外卖订单状态机 | 电商订单状态机 |
| 支付 | 微信支付 | 支付单 + 回调 |
| 通知 | WebSocket | MQ |
| 统计 | ECharts + POI | 搜索聚合 |

## 可复用回答

### 你的项目亮点是什么？

```text
苍穹外卖让我完整走通了需求分析、表设计、接口设计、事务、缓存和支付；
黑马商城让我把单体升级为微服务，重点解决服务治理、分布式事务、消息可靠性和搜索。
```

### 遇到的最大问题？

可以选：

- 订单状态并发更新。
- 缓存与数据库一致性。
- 支付回调幂等。
- 分布式事务补偿。
- 消息重复消费。
- ES 与 MySQL 同步。

### 如何保证接口安全？

- 统一鉴权。
- 参数校验。
- 越权校验。
- 敏感配置服务端保存。
- 支付回调验签。
- 限流和防重放。

### 如何保证高性能？

- 缓存热点数据。
- 异步化非核心链路。
- 分页和索引优化。
- 服务拆分和独立扩容。
- 搜索走 ES。
